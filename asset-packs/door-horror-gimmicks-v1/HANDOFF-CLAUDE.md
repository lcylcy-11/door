## 부품과 배치 주의

### 공통 좌표

현재 게임은 1600×900 논리 좌표, 문 개구부는 `(700,80,488,695)`, 문 이동량은 440이다. 방 원본은 1672×941이므로 원본 픽셀과 게임 좌표를 섞지 않는다. 모바일에서는 크롭이 달라지며 기존 `geometry()`와 같은 변환을 입력 판정에도 적용한다.

PNG의 투명 여백이 크다. 파일 전체 사각형을 물체 경계나 히트박스로 쓰지 말고 `opaque_bbox_xyxy`를 출발점으로 삼는다. 모든 좌표는 제안이며 실제 렌더에서 확인한다.

### 걸쇠

고정판과 이동 봉을 분리했다. **봉은 가이드 고리와 아래 받이 뒤를 통과해야 한다.** 고정판 아래 → 봉 → 고정판의 가이드/받이 부분만 다시 그리는 순서가 필요하다. 같은 고정판 파일을 클립해서 재사용할 수 있다. `manifest.assemblies.latch`와 미리보기에서 시작 좌표·가림 영역을 확인한다. PNG 두 장을 단순히 위아래로 겹치기만 하면 봉이 고리를 뚫고 보인다.

### 눈과 조명

눈에는 눈꺼풀·피부의 부드러운 가장자리가 있다. 문/유리 뒤에서 마스크하고 어둡게 사용한다. 밝은 얼굴 띠 전체를 문 위에 붙이지 않는다. 전면 밝은 배경은 원본과 동일 크기이며 주요 문틀 세 곳의 x축 차이는 0/0/-1px로 측정했다. 전체 픽셀 정합을 보증하는 것은 아니므로, 전환 시 실제 합성에서 점프가 없는지 확인한다. 조명 변화는 배경에만 적용하고 문·손·충돌 상태를 함께 지우지 않는다.

### 스위치와 슬리퍼

스위치는 고정판과 로커 분리 부품이다. 로커는 원본 고정판 좌표계에서 대략 0.52배로 축소해 `(246,364)`에 놓는 출발점이 맞는다. 실제 클릭 면적은 시각 크기와 별도로 읽기 쉽게 확보한다.

슬리퍼는 발끝이 왼쪽이다. 발끝 일부만 문 밑에 들어가고 바닥의 밑창 높이를 맞춘다. 파일 전체가 아니라 물체의 발끝·밑창에 맞춰 버팀목 접점을 정한다. 확대된 물건 획득 장면이나 발/손 애니메이션은 이 팩에 없다.

### 뒤돌아본 방과 서랍

배경은 상단 서랍 앞판이 없는 상태다. 빈 공간은 원본에서 대략 `(449,304,529,97)`이다. 앞판을 별도 이미지로 덮어 닫힌 상태를 만든다. 전체 캔버스 기준 시작 배치는 `(432.75,260.3,560.5,181.2)`이며, 불투명 부분이 빈 공간에 맞도록 계산한 값이다. 미리보기의 +50px 이동은 합성 확인용으로, 실제 서랍 깊이나 정답 이동량이 아니다. 필요하면 측면/내부 그림자를 구현 측에서 보완한다.

뒤쪽 방의 가구 배치는 AI 제작 에셋의 제안이다. 기존 원룸의 확정된 평면도나 캐논을 새로 승인받았다는 뜻이 아니다.

## 사운드 연결

- 모든 WAV는 48kHz/PCM16/스테레오다. 루프는 `loop_start_frame`과 끝 미포함 `loop_end_frame_exclusive`가 있다. 단발 파일은 앞뒤를 0으로 감쇠했다.
- 직접 합성한 Foley다. 현장·성우 녹음이나 외부 음원 라이선스를 주장하지 않는다. 효과음의 감각적 품질과 게임 내 믹스는 아직 UNVERIFIED다.
- 오디오를 사용자 입력 뒤 활성화하고, 일시정지/창 숨김/재시작에 재생과 게임 상태를 함께 멈추거나 정리한다. 타이머로 소리만 계속 진행하지 않게 한다.
- G6의 응답 지연과 G1의 안전 시간은 WAV에 구워 넣지 않았다. 런타임이 실제 행동/재생 gain을 소유한다.
- 낮은 gain으로 시작하고 실제 기기에서 비교한다. 작은 스테레오 위치감이 파일에 포함되어 있으므로 추가 panning을 무조건 중첩하지 않는다.
- 청각만으로 정답을 요구하지 않는다. 위치 자막·손가락·서랍 변화 등 같은 정보를 읽을 수 있는 신호를 유지한다.

## 함께 넣을 때 해결할 충돌

아래는 구현상 안전장치 제안이며 새로운 사용자 결정은 아니다.

1. **일곱 개 포함 ≠ 일곱 개 항상 동시 발생.** 먼저 각 규칙을 단독으로 배울 수 있게 하고, 이후 의미 있는 조합을 만든다.
2. 눈을 피해 아래를 보는 상태와 뒤돌아보기를 동시에 강제하면 한 마우스로 해결 불가능할 수 있다. 같은 순간에 서로 다른 시점 정답을 강요하지 않는다.
3. 손잡이를 유지하면서 시점을 바꿀 입력이 아직 결정되지 않았다. 마우스만으로 돌아보기/놓기/힘 조절을 구분할 수 있어야 한다. 버팀목을 써서 안전한 전환 시간을 만드는 조합은 검토할 만하다.
4. 손이 이미 문을 잡은 상태에서 걸쇠를 억지로 잠그게 하지 않는다. 문 닫힘·버팀목 제거·걸쇠 결착의 조건을 명확히 한다.
5. 소음 마스킹 중에도 시선 금지나 손의 물리 저항까지 무효화되지는 않게 한다. 어떤 위험을 가리는지 예고한다.
6. 모방 응답은 순수 난수 함정이 되지 않게 한다. 가짜 움직임 → 응답의 시차 → 대응 가능 구간이 관찰 가능해야 한다.
7. 앞판이 없어진 뒤쪽 방 배경을 그대로 최종 화면에 사용하면 처음부터 서랍이 열린 것처럼 보인다. 앞판과 상태를 함께 연결한다.

## Claude 작업 완료 기준

- 일곱 기믹 각각의 실제 경로가 있고, 새 소품이 화면에 존재하는 것만으로 완료라고 하지 않는다.
- 기존 느린 문 조작과 H2 힘 조절을 보존하거나, 변경이 필요하면 사용자에게 경험상 차이를 설명한다.
- 실제 마우스로 잡기·지속 드래그·힘 변경·놓기·시점 전환·재시작·성공/실패를 검증한다. H2 자동 완주는 힘 조절에 실제 화살표 키를 사용했으며, 지속 마우스 입력 검증을 대신한 것은 아니다.
- 멈춤, 시선, 서랍과 걸쇠의 상태가 소리·자막과 일치하는지 확인한다. 모순된 동시 요구로 필패하는 조합은 막는다.
- 전면 밝기, 투명 여백, 걸쇠 가림, 서랍 합성을 데스크톱과 좁은 화면에서 확인한다.
- 정상 경로와 각각의 실패 원인을 AI가 먼저 검증한 다음 사용자에게 공포감·손맛·템포를 묻는다.
- 기능 체크, 사용자 경험 수용, 출시 승인을 구분한다. 공개 배포나 원격 푸시는 별도 요청 전에는 하지 않는다.
- 프로젝트의 공용 트래커 한 곳을 계속 사용하고, 작업을 멈출 때 Writer를 해제한다.
